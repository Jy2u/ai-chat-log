## 1. 总览与运行模式

**一句话**：复制文字或图片后，用悬浮条把内容记成提问或回答；课题、文件夹、会话、思维导图、文档、待办、常用内容全部保存在本机。

### 1.1 运行模式

| 行为 | 说明 |
|---|---|
| 复制即记录 | 后台监听系统剪贴板，检测到新文本/图片后在鼠标旁弹出悬浮条（见第 2 章），用户点「提问」或「回答」才入库 |
| 托盘常驻 | 关闭主窗口不退出，只隐藏到系统托盘；首次隐藏时弹托盘气泡提示「AI 对话记录器仍在运行，复制文字仍会弹出悬浮条，可从托盘图标退出」。彻底退出只能从托盘右键菜单选「退出」 |
| 托盘交互 | 托盘菜单：显示主窗口 / 暂停记录（勾选项，与设置、主窗口状态同步）/ 开机自启（勾选项）/ 重启 / 退出。单击或双击托盘图标 = 显示主窗口 |
| 单实例 | 同一时间只允许一个实例。第二次启动时向已有实例发「show」消息，已有实例把主窗口还原置前（含最小化恢复、Windows 前台权限让渡），第二进程随即退出 |
| 开机自启 | 写注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，值名 `AIChatLogger`，命令为可执行文件路径 + `--minimized` 参数（开机后静默驻托盘，不弹主窗口）。每次开启都重写命令，程序挪位置后重新勾选一次即可修正。仅当前用户生效 |
| 重启 | 托盘菜单「重启」：等待本进程退出后重新拉起（避免单实例锁未释放） |
| 崩溃日志 | 启动失败/未捕获异常把堆栈写到 `data/last_error.txt` |
| 数据全本机 | 无网络服务、无账号、无遥测。全部数据存在程序目录的 `data/` 下（SQLite + 图片），备份或换电脑时把整个程序文件夹带走即可 |

### 1.2 启动行为

- 启动时打开数据库并确保至少存在一个会话（完全没有会话时自动建一个名为当天日期 `YYYY-MM-DD` 的会话）。
- 首次显示主窗口；带 `--minimized` 参数时只驻托盘。
- 任务栏使用应用自己的图标（AppUserModelID = `little-tools.ai-chat-logger`）。

## 2. 剪贴板记录

### 2.1 监听流程（main.py `ClipboardWatcher`）

剪贴板每次变化按以下顺序处理，任一步命中即走该分支：

1. **自我复制抑制**：应用内「复制原文/复制图片/常用栏复制」会先设置一次性抑制标志，下一次剪贴板变化直接吞掉（只抑制一次，之后恢复监听）。
2. **隐私标记过滤**：见 2.2。带「请勿监听」标记的内容不记录、不展示、不弹条。
3. **图片识别**：见 2.3，三种形态按顺序尝试，取到图片即弹图片悬浮条。
4. **文本**：无图片时，取剪贴板文本；`strip()` 后长度 < 2 的丢弃。
5. **1.5 秒去重**：部分应用一次复制触发多次信号，相同文本在 1.5 秒内只处理一次（每次触发都刷新时间戳）。
6. 命中后若「暂停记录」开关开启，不弹悬浮条（内容直接丢弃，不入库）。

### 2.2 隐私 MIME 过滤（`_mime_marked_private`）

密码管理器（1Password、KeePass 等）复制敏感内容时会在剪贴板上带约定俗成的「不记录」标记。检测以下格式（原生名与 `application/x-qt-windows-mime;value="..."` 两种形式都查）：

| 格式 | 判定 |
|---|---|
| `ExcludeClipboardContentFromMonitorProcessing` | 存在即视为隐私 |
| `Clipboard Viewer Ignore` | 存在即视为隐私 |
| `CanIncludeInClipboardHistory` | 存在且数据前 4 字节 DWORD == 0（「不许进剪贴板历史」）时视为隐私 |

这是隐私红线：**带这些标记的内容不得记录、不得展示、不得入库**。重写版必须以等价方式（`RegisterClipboardFormat` + `IsClipboardFormatAvailable` / `GetClipboardData`）实现相同判定。

### 2.3 图片三形态（`_image_from_mime`）

| 形态 | 来源 | 判定 |
|---|---|---|
| ① 位图数据 | 截图工具（Win+Shift+S 等） | 剪贴板含图像数据且非空图 |
| ② 单文件 URL | 资源管理器复制图片文件、微信发送框等 | 剪贴板含 URL 列表且**恰好 1 个**、是本地文件、扩展名 ∈ `.png .jpg .jpeg .bmp .gif .webp`，且能成功解码为图片 |
| ③ 纯文本路径 | 微信「复制聊天图片」等场景 | 剪贴板文本 `strip()` 并去掉首尾引号后：以 `file:///` 开头（按 URL 转本地路径），或形如 `X:\...`（第 2 个字符是 `:`、第 1 个字符是字母）；扩展名同上且能解码 |

三形态按 ①→②→③ 顺序尝试，先命中先用。都不命中则按纯文本走（若文本本身是路径但不指向图片文件，会作为普通文本弹出）。

### 2.4 悬浮条（float_bar.py）

无边框、置顶、不抢焦点、不进任务栏的小窗口：

- **布局**：玻璃卡片，左侧缩略图（仅图片）或文字预览，右侧三个按钮——**提问**（蓝色渐变）、**回答**（绿色渐变）、**×**。
- **文本预览**：`已复制 N 字　<压缩成单行的前若干字…>`（空白折叠为单空格，宽度超限省略号截断）。
- **图片预览**：`已复制图片 宽×高`，附等比缩略图（高 34px，超宽再压到 120px 宽）。
- **出现位置**：鼠标指针右下方（+12, +18）；越出屏幕底部时翻到指针上方（−14），再整体 clamp 进可用屏幕区域（四周留 8px）。
- **出现/消失动画**：首次出现 160ms 淡入；超时 200ms 淡出后隐藏。
- **自动隐藏**：3 秒无操作自动淡出；鼠标悬停在悬浮条上时暂停计时，移开后重新计 3 秒。
- **按钮行为**：
  - 提问 → 立即隐藏，内容以 role=user 入库；
  - 回答 → 立即隐藏，内容以 role=ai 入库；
  - × → 直接触发淡出，本次不记录。

### 2.5 入库行为（main.py `on_saved`）

- 写入**当前选中会话**；若当前没有会话，先自动建一个名为当天日期 `YYYY-MM-DD` 的会话（建在当前课题下）。
- 文本消息：`add_message(sid, role, text)`；若这是会话第一条记录且会话仍为自动命名状态，触发自动命名（见 3.4）。
- 图片消息：图片编码为 PNG 存入 `data/images/`（命名规则见 10.3），消息 kind=image，content=文件名；自动命名前缀用「图片」二字。
- 入库后主窗口收到 `notify_message_added`：切到该会话、滚动定位到新消息并高亮闪烁，主窗口还原置前。
- 重写变化：现状 add_message + 自动命名 + 会话时间戳分多次独立事务，重写版改为单事务完成，行为不变、可靠性更好。

## 3. 组织模型

### 3.1 四层结构

```
课题 (subject)
 └─ 文件夹 (folder)          —— 可选层，用来按周期/主题收纳
     └─ 会话 (session)       —— 气泡流
         └─ 记录 (message)   —— 提问/回答，文本或图片
```

会话可直属于课题（根目录），不强制放进文件夹。

**导图和文档可挂三级**：思维导图 (mindmap) 和 Markdown 文档 (document) 可以挂在①课题根目录、②某文件夹下、③某会话下（作为会话的子项显示）。

### 3.2 各对象的通用能力

| 对象 | 新建 | 重命名 | 删除 | 移动 | 复制 |
|---|---|---|---|---|---|
| 课题 | 左侧课题区空白处/课题上右键「新建课题」 | 双击 | 右键「删除课题」（至少保留一个） | —（顶层，拖动换序） | — |
| 文件夹 | 树空白/文件夹右键 | 双击 | 右键（连同夹内全部内容进回收站） | 右键「移动到课题」；拖动换序 | — |
| 会话 | 右键新建，默认名当天日期 | 双击；改名后不再自动命名 | 右键（进回收站） | 拖拽进文件夹/根目录；右键「移动到/移动到课题」 | 右键「复制到」（含消息、图片文件副本、挂在其下的导图与文档） |
| 思维导图 | 右键新建（跟当前选中项同层） | 双击（根节点同步改名） | 右键（进回收站） | 拖拽；右键「移动到/移动到课题」 | 右键「复制到」 |
| 文档 | 右键新建（同层） | 双击 | 右键（进回收站） | 拖拽；右键「移动到/移动到课题」 | 右键「复制到」 |

复制命名规则：原名加「 副本」后缀（已带则不重复加）；空名用「未命名」。复制会话时图片文件会物理复制一份新文件，删除原会话不影响副本。

### 3.3 树交互细节

- **层级混排排序**：同一层内文件夹、会话、导图、文档混合排列，每层共用一套 `sort_order`；新建条目取该层最小 sort_order − 1（新条目排最前）。排序键为 `(sort_order, -id)`（同序号时新建在前）。
- **拖拽**：
  - 拖条目到文件夹上（on）= 放进该文件夹（会话/导图/文档）；拖到会话上（on）= 挂到该会话下（仅导图/文档）。
  - 拖到条目上/下边缘（above/below）= 同层换序。
  - 文件夹只在顶层之间换序，不会嵌套进另一文件夹（拖到嵌套条目上时提升到其顶层祖先的下方）。
  - 拖会话到「会话下的导图/文档」附近时，目标会话作为参照（会话不能挂到会话下，落为其下方兄弟）。
  - 落进新文件夹时条目排到该层最前。
- **展开状态**：文件夹展开/收起由点击切换（点击文件夹不切换选中，只展开/收起；选中态还回当前会话/导图/文档），展开状态按课题持久化。
- **行内元素**（详见 UI 设计文档）：文件夹行右侧有【匹配】和【导入】两个小按钮；会话行右侧可画 chip 标签，鼠标悬停 200ms 显示备注气泡。
- **双行时间**：会话/导图/文档条目下方显示创建时间和最后编辑时间两行小字。

### 3.4 会话属性

| 属性 | 说明 |
|---|---|
| 自动命名 | 新建时默认名为当天日期，`auto_named=1`；第一条记录入库时自动改为 `日期-内容前缀`（前缀 = 内容压缩单行、去掉行首 `# > * \` -` 等符号后取前 10 字）。用户手动改名后 `auto_named=0`，永不再自动命名 |
| 备注 (note) | 右键「添加备注/编辑备注」，玻璃对话框编辑；鼠标停在会话条目上 200ms 显示气泡 |
| source 标签 | 右键勾选【cursor】或【codex】二选一（再点取消）；chip 画在条目右侧、不挤占文字。Cursor 导入自动打 cursor 标签 |
| 已完成 (done) | 右键勾选【已完成】；显示「已完成」chip，未完成不显示 |
| 颜色匹配 (match_color) | 见 3.5 |
| 最后编辑时间 (updated_at) | 新增/删除消息、节点编辑、内容更新时刷新；显示在条目第二行 |

### 3.5 颜色匹配

文件夹行右侧【匹配】按钮的三段式流程：

1. **第一次点【匹配】**：进入点选模式（该文件夹自动展开；夹内无会话时提示「这个文件夹里还没有对话可以匹配」并退出）。状态栏提示「正在匹配：点选要绑定的对话，再点【匹配】选择颜色」。
2. **点选会话**：夹内会话逐个点选/再点取消，状态栏实时显示「已选 N 个对话…」。
3. **第二次点【匹配】**：已选会话时弹出颜色选择浮窗（五种颜色：亮橙色、淡粉色、淡蓝色、灰色、淡紫色 + 清除匹配）；未选时直接退出匹配模式。

- 同色会话在树中一起高亮。
- 退出方式：Esc、空选再点【匹配】、点选夹外区域。
- 右键有匹配色的会话：「导出匹配的全部对话（颜色名 · N 个）」和「取消颜色匹配」。
- 匹配关系限定在**同一课题、同一文件夹**内同色的会话。

### 3.6 课题切换

- 点课题切换工作区（保存并恢复每个课题各自最后选中的会话/导图/文档视图）。
- 双击课题重命名；课题列表可拖动换序；右键新建/重命名/删除。
- 删除课题时统计文件夹/会话/记录数并确认，至少保留一个课题。
- 回收站恢复/搜索跳转到其他课题的会话时自动切换课题。

## 4. 思维导图

### 4.1 数据模型

- 节点两种 kind：**box（子框）**——带边框的框；**text（子句）**——无边框文字。
- 每图有一个中心框（root，无父节点中 id 最小者），建图时自动创建、内容 = 导图名。编辑中心框内容会同步导图名（反之重命名导图时若根节点内容仍是旧名也同步）。
- 连线独立成表（from/to/label），与父子关系并存：加节点自动建父子连线；手动连线不拆除已有连线；删除连线两端节点保留。
- 节点可记录：位置 pos_x/pos_y、手动尺寸 box_w/box_h、边标签 edge_label（旧数据，现标签在 edge 表）、高亮 highlighted、创建/编辑时间。

### 4.2 视图与布局

- 无坐标节点自动布局：子节点放父节点右侧（水平间距 56、垂直间距 18），多棵散树从左往右排；已有坐标一律不动。首次布局算出的坐标会回写数据库。
- 节点尺寸按内容估算（中文约 1 宽、西文约半宽），box 最小 168×46、text 最小 140×38；手动调过大小后以记录值优先。
- 多行长文本节点左对齐（mm-prose），短标题居中。
- 顶部固定操作提示条。

### 4.3 交互（render_mindmap_js.py）

| 操作 | 行为 |
|---|---|
| **中键拖动框选** | 按下中键画橡皮筋选框；与选框相交的**节点和连线一起选中**（贝塞尔曲线按 24 段采样判定与矩形相交）；被选中连线的两端节点自动并入选择。框选后可整体拖动。重写版需禁用浏览器中键自动滚屏（旧版注入 `--disable-features=MiddleClickAutoscroll`） |
| **拖背景** | 左键按住空白处拖动 = 移动画布（pan），松手时保存视口 |
| **Ctrl + 滚轮** | 以鼠标为锚点缩放，范围 0.4×–2.5×，每次 ×1.12；视口（tx/ty/scale）持久化，重开导图恢复 |
| **点节点** | 选中：显示左右两个连接点和四角缩放手柄 |
| **四角拖动** | 改节点尺寸（box 最小 100×36、text 最小 80×36，最大 900×1400），松手落库 |
| **连接点拖线** | 从左/右连接点拖出虚线到目标节点松手 = 建连线（右端口为起点、左端口为终点）；拖到空白取消 |
| **拖节点** | 长按 180ms（或移动超 6px）后拖动；默认拖动整个子树，框选多选状态下拖动整组；松手批量落库（setpos 单事务） |
| **双击节点** | 进入行内编辑（contentEditable），Enter 结束（box 类；text 类 Enter 换行）、Esc 放弃、失焦保存 |
| **双击连线标签** | 直接编辑标注 |
| **点连线** | 选中连线，显示两端手柄 |
| **拖连线端点手柄** | 把连线一端改接到其他节点（relink），不动其他连线 |
| **Esc** | 取消框选 / 取消连线拖拽 |
| **右键菜单** | 见 4.4 |

### 4.4 右键菜单（3 处）

**右键节点**（先显示创建时间/编辑时间两行元信息）：

| 菜单项 | 行为 |
|---|---|
| 新建子框 / 新建子句 | 在该节点下新建 box/text 子节点（新子节点自动放父节点右侧、已有兄弟下方） |
| 高亮 / 取消高亮 | 切换节点高亮；两端都高亮的连线也高亮显示 |
| 只删除此单元（非中心框） | 删除该节点，子节点接到它的父节点（同层保序插入），与该节点相关的连线首尾直连（保留原标签） |
| 删除此单元及后续（非中心框） | 确认后递归删除整个子树 |
| （中心框） | 不提供删除项——「中心框请在左侧删除整张导图」 |

**右键连线**：在连线上新建子框 / 在连线上新建子句（在连线中点插入新节点，原连线拆成两段、标签随下游段）、编辑标注（输入框「两端单元的关系：」）、删除连线（确认「单元本身会保留」）。

**右键空白**：新建独立子框 / 新建独立子句（无父节点，落在右键位置）。

### 4.5 连线规则（db_mindmaps.py）

- 不能连到自己、不能连到其他导图；同向重复连线拒绝（「这两点之间已经有连线了」）。
- 连线目标节点若无父且非中心框，新连线起始节点收编为父。
- 删除连线后：若目标节点再无入边 → 变为独立单元；若还有其他入边 → primary parent 切到最早入边的起点。
- relink 同样受去重与自连限制，改端后刷新两端的 primary parent。

### 4.6 导出

导图随文件夹 zip 导出为 Markdown（大纲 + Mermaid 流程图，格式见 9.3），无单独导出入口。

## 5. Markdown 文档

- **布局**：左编辑右预览分栏；顶部显示「文档「名」 · Markdown · 左侧编辑，右侧预览」。
- **自动保存**：输入 420ms 防抖后自动保存（`savedoc`），失焦（blur）立即保存。
- **预览**：与聊天气泡同一套 Markdown 渲染（见 5.1）；保存后只局部刷新预览区，编辑器不清空不重建；空文档显示「还没有内容，左边写 Markdown，右侧即时预览」。
- **语法帮助**：工具栏「markdown语法」按钮弹出说明窗口（含样例）。
- **导出**：右键文档「导出 Markdown」，保存为 .md（文件名默认文档名，非法字符替换为 `_`）。

### 5.1 Markdown 渲染规则（render.py `md_to_html`，文档与气泡共用）

- markdown-it `commonmark` 预设 + `table` + `strikethrough`；`breaks: true`（单个换行即换行）；**`html: false`**——粘贴的原始 HTML 一律按文本转义，防止页面被打乱。
- 代码块语法高亮（pygments monokai → 重写版 highlight.js monokai），带语言标签。
- **KaTeX 公式**：渲染前先抽公式（避免 Markdown 吃掉 `_`、`|`、`[]`），支持：
  - `$$...$$`、`\[...\]`（行间）；
  - 单独成行的 `[` 换行块 `]`（形态粗筛像 LaTeX 才当公式，避免误吞普通列表）；
  - `\(...\)`、`$...$`（行内，`$` 前后不能紧贴字母数字）；
  - 代码块与行内代码先摘出，不参与公式识别。
- **Cursor Canvas JSX**：整段内容是从 `from "cursor/canvas"` 导入的 TSX/JSX 代码块时，不按代码块渲染，而是解析成卡片/表格布局（`render_canvas.py`：判定 → 去 TS 类型 → 解释执行 const/函数/map/循环/条件 → JSX 树 → 静态 HTML）。重写版移植为 `canvas-renderer.ts`。
- 远程资源拦截：预览/气泡里粘贴的远程图片（`![x](http://...)`）一律不加载（防泄 IP）；http(s) 链接点击转系统浏览器打开；file:// 链接只放行本应用 images 目录，指向其他本地文件的链接拦截并提示。

## 6. 待办

窗口最右侧固定 260px 的玻璃面板。

### 6.1 添加与日期解析（`parse_dated_todo`）

- 输入框 + **+** 按钮或回车添加；空内容忽略。
- 正则 `^【?\s*(\d{4})-(\d{1,2})-(\d{1,2})-(.+?)\s*】?$` 识别 `年-月-日-事情`（可带【】包裹）：
  - 日期合法且事情非空 → 拆出日期；展示正文为「事情」部分（去掉多余前导 `-`）。
  - 日期非法或事情为空 → 整条按普通待办。
  - 例：`2026-09-11-交报告` → 日期 2026-09-11，正文「交报告」。
- 输入框占位提示 `2026-09-11-事情`。

### 6.2 分组与排序

- 同一天的待办归在一个日期玻璃框下（标题 `YYYY-MM-DD`，颜色按天在五色匹配色中轮换：日期序号 % 5）；**日期新的组在前**。
- 无日期待办不分组，跟在日期组后面。
- 每个日期组内分**未完成**与**已完成**两段：未完成按（标记权重：不做了=2 > 延后=1 > 无=0，sort_order，新建在前）排；已完成按（sort_order，新建在前）排。「已完成」标题仅在有已完成项时显示。
- 新待办 sort_order 取当前最小 − 1（排最前）。

### 6.3 行操作

| 操作 | 行为 |
|---|---|
| 圆圈 | 标记完成（✓、文字划线、移到已完成段）；再点一次移回未完成 |
| **单击**条目正文 | 在标题下展开备注编辑框（占位「添加备注」）；回车/失焦保存，Esc 取消；有备注时以小字显示 |
| **右键** | 菜单：【延后】/【不做了】（勾选切换，二者互斥）、取消标记；标记显示为条目右上角玻璃 chip |
| **×** | 删除该待办 |

标记取值仅 `later`（延后）/`skip`（不做了）/ 空，其他值一律归空。

## 8. Cursor 导入

### 8.1 数据来源与读取方式（cursor_import.py）

- 读取 Cursor 本机数据库 `%APPDATA%\Cursor\User\globalStorage\state.vscdb`（环境变量 `CURSOR_APPDATA` 可覆盖路径，指向 User 目录或其父目录均可）。
- **只读快照**：以 `file:...?mode=ro` URI 只读连接，不复制数 GB 数据库、不写入；Cursor 正在聊天时新消息可能要到下次打开列表才出现。
- 会话头列表来自 `cursorDiskKV` 表 `composerData:%` 前缀键；消息正文按 `bubbleId:{composerId}:{bubbleId}` 批量 IN 查询（每批 300 个）。
- 找不到库文件/没有 cursorDiskKV 表时报中文错误。

### 8.2 会话列表与选择

- 列表按更新时间倒序；每项含标题（空则「未命名对话 {id前8位}」）、工作区（取 workspaceIdentifier 名称）、更新时间、**对话轮数**。
- 轮数 = headers 中真实用户提问数（type==1、非模拟、可渲染），不是消息总数（headers 还包含 thinking、工具调用和内部状态）。
- 选择弹窗：玻璃表格（标题/工作区/更新时间/对话轮数 四列，单选、双击行或点「导入」确认），提示「列表只读取本机缓存，不会修改原始数据」。

### 8.3 消息提取与过滤

对每个 bubble（消息气泡）：

| 过滤 | 规则 |
|---|---|
| 不可渲染 | header `isRenderable == false` 丢弃 |
| 能力卡 | capabilityType 非空一律丢弃。TOOL_LABELS = {15:工具调用, 19:终端, 30:思考, 33:计划, 40:读取文件, 41:编辑文件, 42:创建文件, 50:搜索, 60:浏览器} |
| 思考片段 | text 是 JSON 且含 `isLastThinkingChunk` 的丢弃 |
| 角色判定 | type==1 且非模拟消息 → user，否则 ai |
| 正文提取 | text 为字符串且非空直接用；否则递归解析 Lexical 富文本 JSON（text/linebreak 节点，段落与标题后补换行，深度限 32） |
| 图片 | 用户消息的 `selectedImages[].path`（本地路径）逐张生成独立 image 消息；图片从原路径复制进 `data/images/`（data URL 按 MIME 解码并映射扩展名；单张上限 50MB，超限报「单张图片超过 50 MB，已拒绝导入」） |
| 空消息 | 无正文且无图片的丢弃 |

### 8.4 轮次收敛

每轮只保留**用户原文 + 下一条用户消息前的最后一个 AI 输出**（中间的 AI 输出丢弃）。这是对「一问一答」展示方式的收敛：Cursor 中间过程没有稳定字段标记，用轮次边界比枚举内部类型可靠。开头连续多条用户消息保留到首个 AI 输出一起落库；末尾没有 AI 回复的用户消息不落库。

### 8.5 落库（db.py `import_external_conversation`）

- 导入到指定文件夹；会话名 = 对话标题，created_at/updated_at 取自 Cursor 时间戳（缺省用当前时间）。
- `source='cursor'` 标签自动打上。
- **重复导入生成副本**：同一 composerId 可重复导入到任意文件夹，每次都是独立副本。表结构保留唯一键以兼容旧库，重复时外部实例键用 `composerId#uuid4hex`，原始 composerId 完整保存在 raw_metadata（含 workspace/createdAt/updatedAt/mode/turnCount）。
- 原子写入：单事务；任一步失败回滚并删除已写入的图片文件。
- 导入成功后树中选中该会话，状态栏「已从 Cursor 导入：标题（N 轮）」。
- codex 来源在库层支持（source ∈ {cursor, codex}），当前界面入口只有 Cursor。

## 9. 搜索、回收站、导出、备份

### 9.1 搜索

- 顶栏搜索框（占位「搜索全部记录，回车确认」，240px，带清空按钮）：回车触发，跨全部会话按消息内容模糊搜索。
- 结果页：每条命中显示所属会话名（点击跳转到该会话并定位；跨课题自动切换课题）+ 气泡（无操作链接）；标题「搜索「关键词」，共 N 条结果」。
- 上限 200 条，按消息 id 倒序（新的在前）。
- 清空搜索框或切换会话即退出搜索模式，回到原视图。
- 当前实现：`content LIKE %kw% ESCAPE '\'`（`% _ \` 转义），跳过已软删除会话。
- **重写变化**：改用 SQLite FTS5 `MATCH` 全文索引（messages_fts 虚表 + 触发器同步 + 存量回填）。FTS 分词与子串匹配的命中集差异属预期可接受变化；查询含 FTS 特殊字符导致语法错误时回退 LIKE。

### 9.2 回收站

- **软删除**：课题/文件夹/会话/导图/文档删除一律写 `deleted_at` 时间戳（不是物理删除）；删文件夹连带夹内会话/导图/文档，删课题连带其下全部，删会话连带挂其下的导图/文档。
- **回收站页**：只列「顶层」条目（夹在里面的子项随父级一起恢复，不单独列出；父级仍在回收站里的子项不显示）。每项显示类型（课题/文件夹/会话/思维导图/文档）、名称、所在位置（课题/文件夹/会话链）、规模（文件夹/课题显示 N 个会话、会话显示 N 条记录）、删除时间，按删除时间倒序。顶部「清空回收站」。
- **恢复**：条目自身 + 全部后代恢复（`deleted_at` 置 NULL）；祖先链（所在会话/文件夹/课题）若也在回收站里一并恢复。恢复后自动切换到对应课题并展开所在文件夹。
- **彻底删除**：二次确认后物理删除。课题/文件夹/会话删除时其引用的图片文件一并删除；导图删除同时丢弃其视口缓存。
- **清空**：确认后物理删除全部已软删除行，返回待删图片清单并删除文件。
- 消息级删除：气泡上「删除」确认后直接物理删除（消息不进回收站；图片消息同时删图片文件）。

### 9.3 导出

| 导出 | 入口 | 产物 |
|---|---|---|
| 单会话 Markdown | 右键会话「导出 Markdown」 | 一个 .md：一级标题=会话名，引用行「创建于 X · 导出于 Y · 共 N 条记录」，每条消息 `---` 分隔 + `**我/AI** · 时间` + 原文；图片消息为 `![图片](路径)`（单会话导出用 file:// 绝对路径） |
| 同色批量 Markdown | 右键带匹配色的会话「导出匹配的全部对话（颜色 · N 个）」 | 选目录后建 `匹配-颜色名` 文件夹（重名追加 `-2`）：每个会话一个 .md（文件名去非法字符、限 80 字符、重名加序号），图片集中复制到 `images/`，md 内引用 `images/文件名` |

| 文档 Markdown | 右键文档「导出 Markdown」 | .md = 文档原文内容 |

### 9.4 备份与自动备份

- **手动备份**：工具栏「备份整个软件」→ 输入备份原因（必填，非法文件名字符剔除）→ 执行。
- **产物**：`~/Documents/AIChatRecord备份/{YYYY-MM-DD-HH点MM分}-{原因}`（重名追加 `-2`）目录，内含整个程序文件夹副本（跳过 `__pycache__`、`.git`、`.cursor`、`.idea`、`.vscode`、`*.pyc`、`chatlog.db`/`-wal`/`-shm`）+ 通过 SQLite Online Backup API 热备的 `data/chatlog.db`（避免直接拷贝运行中的库导致损坏）+ 图片。状态栏报告「已备份到 X（程序文件 + 数据库 + N 张图片）」。

- **自动备份**：每 6 小时一次（锚点 = 上次自动备份时间，无则首次启动时间）；失败 30 分钟后重试。工具栏常驻倒计时标签：「上次自动备份 YYYY-MM-DD HH:MM · 下次还有 X小时Y分」或「尚未自动备份（起始 …） · …」，进行中显示「正在自动备份」。
- **重写变化**：定时器由 Qt QTimer 改为 Rust 后台任务，行为（6h 间隔、30m 重试、倒计时展示）不变。

### 10.3 图片文件命名（两种规则）

| 来源 | 命名规则 | 示例 |
|---|---|---|
| 剪贴板图片（悬浮条入库） | `{YYYYmmdd-HHMMSS}-{md5(PNG字节)前8位}.png`（统一转码为 PNG） | `20260916-143025-1a2b3c4d.png` |
| 外部导入（Cursor selectedImages 等） | `{uuid4 hex}{原始扩展名}`；data URL 按 MIME 映射扩展名（jpeg→.jpg 等，未知→.png）；独占创建（`xb` 模式）；单张 ≤ 50MB | `9f8e7d6c...354453627180.png` |

同图短时间内重复复制（剪贴板路径）因带时间戳会生成新文件；复制会话时图片物理复制为新的 uuid 文件名。

### 10.4 回收站语义

回收站 = 五张主表（subjects/folders/sessions/mindmaps/documents）的 `deleted_at` 软删除。所有列表查询一律过滤 `deleted_at IS NULL`；恢复 = 置 NULL；彻底删除/清空 = 物理 DELETE（先收集待删图片文件清单，删除行后删文件）。消息（messages）不参与软删除——气泡删除即物理删除。

### 10.5 设置持久化

- 旧版用 QSettings（注册表 `HKCU\Software\little-tools\ai-chat-logger`）：侧栏宽度（subject_width/folder_width/sidebar_width）、sidebar_dragged、文件夹展开状态（expanded_folders_{subject_id}）、每课题最后选中项、current_subject_id、current_session_id、last_export_dir、last_auto_backup_at、auto_backup_start_at。
- **重写变化**：UI 偏好改为 exe 同目录 `data/settings.json`，键值承接上述全部语义（含导图视口 _mm_view）；旧注册表不迁移，首次运行取默认值。这属计划决策，非行为要求。

### 10.6 迁移（重写版约定）

旧库兼容：db.py 现状每次启动跑全表迁移扫描（补列、edges 物化、导入噪声清理、混排排序初始化）。**重写变化**：改为 `meta(schema_version)` 版本化增量迁移——旧库一次性补齐到 version 1 基线（含全部 ALTER 与数据回填），此后启动只比对版本号，不再全表扫描；v2 补外键索引、v3 建 FTS5 表。功能等价，启动行为不同。
